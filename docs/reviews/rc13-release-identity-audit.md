## Root cause

Every script that derives its version from `packageJson.version` at run time
stays consistent automatically. Every site that stores the version as a
separate literal (the lockfile's two `version` fields, the release contract
JSON, the CLI test's expected string, and the traceability script's fallback
string) requires a manual, easy-to-forget update. This is exactly the pattern
that already caused the historical `rc.8`-reported-on-`rc.11`-build defect
referenced in `src/config/application-version.ts`'s own comment, and it
recurred here for `package-lock.json` and the release contract during the
rc.12 release.

`scripts/validate-release-artifacts.mjs` already contains the guard that
would catch the contract/package mismatch (line 46-47), but it is a release
gate, not a pre-commit or CI-on-every-push check — it was not run between the
rc.12 merge and this audit.
